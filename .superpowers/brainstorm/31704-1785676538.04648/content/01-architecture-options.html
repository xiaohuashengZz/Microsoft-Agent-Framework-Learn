合同管理 Agent 系统 - 架构方案选型

基于 .NET MAF (Managed Add-in Framework) + Vue.js 前后端分离架构，请选择最适合你的方案

A

🏗️ 经典分层 MAF 插件架构 （推荐）

MAF 作为核心插件容器，每个业务能力独立为 Add-in

架构分层：
🔷 Host 层：ASP.NET Core Web API + MAF AddInStore
🔷 Contract 层：IContract 契约定义（IAgent, IGenerator, IReviewer）
🔷 Add-in 层：合同生成插件、合规审查插件、搜索插件、Word填充插件
🔷 View 层：HostView / AddInView 适配器
🔷 Pipeline：自动生成的 Add-in Pipeline 目录

✅ 优势

  • 严格遵守 MAF 设计模式
  • 插件完全隔离，可独立部署
  • 支持版本控制和热插拔
  • 学习 MAF 框架最佳实战

⚠️ 注意

  • Pipeline 配置相对复杂
  • 契约变更需要重建 Pipeline
B

🔌 简化版 MAF + DI 混合架构

MAF 管理核心 Agent，内部用 DI 组织具体能力

架构分层：
🔷 Host 层：ASP.NET Core Web API + MAF + Autofac
🔷 Contract 层：仅定义 IAgentPlugin 顶层接口
🔷 MAF Add-in：合同Agent插件（内部用DI组合4个子能力）
🔷 核心服务：GeneratorService, ReviewService, SearchService, WordFillService
🔷 共享 DLL：Domain Model, DTO, Abstractions

✅ 优势

  • 开发效率高，MAF 接口简单
  • 内部用 DI 易扩展和测试
  • MAF 负责核心隔离能力
  • 兼顾学习 MAF 和实用价值

⚠️ 注意

  • 子能力不是独立 MAF 插件
  • 隔离粒度较方案 A 粗
C

🧩 微内核 MAF 多 Agent 架构

每个功能都是独立 Agent 插件，由编排引擎协调

架构分层：
🔷 Host 层：Agent 编排引擎 + MAF PluginStore
🔷 Contract 层：IAgent, IPipelineStep, IContext
🔷 Agent Add-ins：TemplateAgent, ReviewAgent, SearchAgent, WordAgent
🔷 编排层：Workflow 定义（生成→审查→填充→归档）
🔷 消息总线：Agent 间事件通信 (MediatR)

✅ 优势

  • 最符合 Agent 理念
  • 每个 Agent 可独立开发/替换
  • 工作流可视化编排
  • 最灵活，扩展性极强

⚠️ 注意

  • 复杂度最高，学习曲线陡
  • 编排逻辑工作量大
  • 调试难度相对高
